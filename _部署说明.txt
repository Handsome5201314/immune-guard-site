二、怎么部署
  1. 把根目录下全部 *.html、version.json、sitemap.xml、robots.txt 和 assets/ 一起上传
  2. 可以放根目录，也可以放子目录（线上现挂在 /immune-guard/）；页面内部全是相对路径，不用改
  3. 不需要 Node、不需要构建、不需要数据库，任何静态 Web 服务都行
     - Nginx / Apache：直接丢进 root 目录
     - 腾讯云 COS / 阿里云 OSS：开启静态网站功能后上传
     - Vercel / Netlify / Cloudflare Pages：整个目录拖进去
  4. 一键发布（推荐）：bash tools/deploy.sh
     - 自动重新生成 version.json → 提交并推送 GitHub → 备份服务器目录 → 上传全部文件 → 验证线上版本
     - 加 --dry-run 只演练不上传；加 --release 连 APK Release 一起发

三、Nginx 参考配置
  location / {
      index index.html;
      try_files $uri $uri/ /index.html;
  }
  location /assets/ {
      expires 7d;
      add_header Cache-Control "public";
  }
  # 版本缓存不要长缓存，发新版后要立刻生效
  location = /version.json {
      add_header Cache-Control "no-cache";
  }

四、版本数据怎么更新（重要）
  - 数据来源两条：① 同目录 version.json（秒开）② GitHub Release API（后台校对）
  - version.json 由 scripts/sync_versions.py 生成（deploy.sh 已自动调用）：
      cd 免疫卫队伍/03-产出/官网设计
      python scripts/sync_versions.py
  - 发新版流程：在 GitHub 建 Release（CI 自动同步 APK 与说明）→ 跑一次脚本 → 重传 version.json
  - GitHub 慢或不可达时页面不会卡住：version.json 先渲染，GitHub 请求 6 秒超时后静默降级，
    版本号/大小/日期/SHA-256 仍正常显示（已实测：阻断 api.github.com 后页面照常可用）
  - 历史版本（v0.6.0 / v0.5.2 / v0.5.1 / v0.5.0）只做版本记录，不提供安装包下载

五、构建与校验（改页面必看）
  页面由分片拼装，不要直接改 *.html，改 _parts/ 后重新构建：
    python tools/build.py              # 构建全部页面
    python tools/build.py index        # 只构建首页
  校验链（提交前建议全跑）：
    python tools/check.py *.html       # 标签配对 / 乱码 / 坏属性 / 重复 id / 锚点与资源
    python tools/link-check.py         # 全站跨页锚点与文件引用
    node tools/render-check.js *.html  # 6 断点：console 错误 / 失败请求 / 横向溢出 / 破图
    node tools/demo-test.js            # 成长页互动演示 19 项断言
    node tools/dl-test.js              # 下载页版本降级路径
    BASE=https://www.xiaozhiserver.cloud/immune-guard/ node tools/live-check.js   # 线上验证
